# Инвентаризация BL-159: тип гейта во всех документах проекта

## Summary / BLUF

BL-159 выполним в одном PR, кроме одного пункта. Где гейт процесса BCREQ
говорил «human gate» или «решение человека», теперь назван тип гейта
(`человек`, `гибрид`, `llm`, `код`) и ключевость по КГ-1…КГ-4 словаря
потока. Остаток поиска — 67 мест в шести категориях. Ни одно из них не
описывает гейт процесса без типа. Пять мест ADR-003 заблокированы решением
владельца Р-16: поправка 0.2 подготовлена, но не применена (BL-162).
Промпты (BL-156), пакет для Хаба (BL-122) и данные журнала К-34 по Г-IN
(BL-161) отложены по ранее принятым решениям. Остаток закреплён
валидатором `scripts/validate_issue_433_gate_types.py`: новое место без
типа или новое исключение без причины ломает `make validate-full`.

## Context / Scope

- **Предмет учёта.** Строки активных документов, где гейт или точка
  решения названы без типа.
- **Охват.** Все отслеживаемые Git файлы `*.md`, `*.json`, `*.yaml`,
  `*.yml`.
- **Что не меняется.** Исторические и порождаемые слои: `docs/analysis/`,
  `docs/audit/`, `runs/`, `experiments/`, `site/data/`, `prompts/archive/`,
  `pr-ops/archive/`, `CHANGELOG.md`. Они фиксируют факт на дату (карточка
  BL-159, «Что меняется»).
- **Метод.**
  [`experiments/issue_433/scan_untyped.py`](../../experiments/issue_433/scan_untyped.py)
  ищет «human gate», «G-human», «человеческий гейт», «решение человека»,
  «подтверждение человека», «human-in-the-loop». Место считается
  типизированным, если в окне ±2 строки есть тип в обратных кавычках,
  слова «тип гейта» или «ключев…».
- **Правки.** Вносились идемпотентными скриптами
  [`apply_gate_typing.py`](../../experiments/issue_433/apply_gate_typing.py)
  и
  [`apply_class_gate_types.py`](../../experiments/issue_433/apply_class_gate_types.py):
  повторный запуск ничего не меняет.

### Противоречие «молчание = согласие»

ADR-0003 вводит «молчание = согласие» для приёмки PR в креативном режиме.
Стандарт процесса и ADR-009 ссылались на это правило для G1–G3.
Словарь потока (правило 4) запрещает считать молчание согласием на гейте.
Разрешение такое:

- ADR-0003 не меняется. Правило остаётся для PR, и его требуют
  валидаторы #61 и #72.
- В стандарте процесса и ADR-009 ссылка заменена правилом 4 словаря.
- Явное правило С6 «разводит ADR-0003 и гейты процесса» войдёт в
  онтологию с поправкой 0.2 (BL-162).

## Recommendations

1. **Владелец: Р-16 (вариант А) → BL-162.** Применить таблицу «Было →
   станет» поправки 0.2, снять пометки «проект» и переключить
   `R16_ACCEPTED = True` в валидаторе #433. До этого BL-151 ссылается на
   словарь потока, а не на ADR-003.
2. **BL-151 и BL-230 пишут тип гейта с первой редакции.** Валидатор #433
   поймает гейт без типа в новых документах, если в них есть искомые
   слова.
3. **BL-156:** тип гейта в CB-0.5 и в строке отказа 14 промптов, затем
   удалить категорию P из исключений валидатора.
4. **BL-161:** заполнять поля `model_recommendation` и `divergence` в К-34
   на прогонах BL-157. Без сводки Г-IN остаётся ключевым `гибрид`.
5. **BL-122:** если Р-12 откроет передачу, типизировать пакет для Хаба и
   удалить категорию T.
